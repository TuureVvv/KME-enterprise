# v4.0 verification

The authoritative local result is `outputs/V4-LOCAL-VERIFICATION.json`, written only after all required suites pass. Detailed outputs are retained in `outputs/V4-RUNTIME-LOG.json`. Publication is separately recorded in `outputs/DEPLOYMENT-v4.0.json`; preparing this document is not deployment evidence.

The release suite covers 112 groups: exact rarity/resonance/theme/smoothing and continuous-engine rules; isolated PostgreSQL reset/merge/archive/admission/receipt/competition tests; full profile/collection/faction/art/transit browser flows; smoothing pixels/recovery; retained combat and 750 modifier compositions; shop/loot/coherence; full-resolution studio opacity/layers/download; standalone rendering/disposal; social, noticeboard and message recovery; all three audio lifecycles; final compact phone layouts and reduced motion. The final verification record contains the actual counts and asset fingerprints.

Browser tests block the real backend and use local fixtures only. Database tests run in an isolated embedded PostgreSQL database after the complete existing schema/migration chain. They do not create test posts, plays, votes or nicotine reports in the real crew. SQL mutation locks and once-only receipts are checked, but the embedded database does not simulate independent simultaneous production connections.

The million-outcome odds check is exhaustive in both JavaScript and PostgreSQL: Aether has exactly 1,000 outcomes. Cryptographic random-byte rejection and uniform variant selection avoid modulo bias. Individual sequences remain random; no fixed number of capsules guarantees an aura.

Existing tests were adapted where v4 intentionally changes the product: the v4 start RPC replaces the old start call; own-profile navigation replaces an own-character popup; the inline Collection tab replaces a wardrobe modal; continuous transit replaces the previous overtime bargain. The splash fixture uses fixed low-health targets because district ecology now replaces generic stalkers. Mission fixtures remove new tremor patrol interference after separately checking damage cancellation. No unchanged shop, combat, art-pixel, message-preservation or consent assertion was dropped. Passing suites were retained while failed expectations were corrected; the final header adjustment receives additional dedicated phone checks.

Screenshots under `outputs/previews/v4-*` cover the profile, catalogue, transit, and 320/360/390 portrait and 844 landscape game layouts. Final phone checks confirm compact headers, readable unobscured health, mission separation, all touch targets inside the viewport and reduced-motion effects. Existing social checks cover 320–1920px. Physical phones, speaker quality and prolonged real-device thermal performance were not manually tested.

The v3.5 baseline was verified and preserved before rebuild. Release preparation scans for private-key markers and records Git blob/SHA-256 fingerprints. Publishing must use the existing Pages branch with an expected-head lease, preserve unrelated tree entries, and verify the successful Pages run, public files, anonymous API denials and an isolated public-demo play. Backend advisories are reviewed against the intentionally closed private tables and admitted shared-character RPC model.

Practical limits: friend-group scores remain client-reported; temporary combat worlds do not survive a reload; provider quotas are finite. The aura archive and one-time currency merge deliberately change collectible/currency state only as requested. Weekly achievements finalize idempotently when a new operation is read, rather than depending on a new scheduled job.
